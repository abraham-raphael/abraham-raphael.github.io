Verifying payment webhooks in C#

A school payment service I built in December 2025 with Clean Architecture: fees in through Paystack, staff salaries out. Here is the code that decides whether a payment notification is genuine, and the change I would make to it today.

Project
School payment service, my own; the code is public
Stack
C#, ASP.NET Core, MediatR, MassTransit, Entity Framework Core, SQL Server, Paystack
Code
github.com/abraham-raphael/Payment_Service

The problem

When a parent pays school fees, Paystack calls the service back with a webhook saying the charge succeeded. Anyone on the internet can send a request to that address, so the service has to prove each one came from Paystack before it marks a fee as paid. Paystack signs every webhook body with HMAC-SHA512 using the merchant's secret key and sends the result in a header.

The code as written

public bool VerifySignature(string body, string signature)
{
    var secretKey = config["Paystack:SecretKey"];
    if (string.IsNullOrEmpty(secretKey)) return false;

    var keyBytes = Encoding.UTF8.GetBytes(secretKey);
    var bodyBytes = Encoding.UTF8.GetBytes(body);

    using var hmac = new HMACSHA512(keyBytes);
    var hashBytes = hmac.ComputeHash(bodyBytes);

    var hash = BitConverter.ToString(hashBytes).Replace("-", "").ToLower();

    return hash == signature;
}

What it gets right

  • It fails closed. With no secret key configured, every webhook is rejected rather than accepted.
  • The check comes first. The handler verifies the signature before it parses the payload or touches the database.
  • It is safe to receive twice. A payment moves from Pending to Successful only once, so a repeated webhook changes nothing.

What I would change

The last line compares two strings with ==, which stops at the first character that differs. In principle that lets an attacker learn, from response times, how much of a forged signature is correct. The fix is a comparison that takes the same time whatever the input, plus explicit handling of a missing or malformed header:

public bool VerifySignature(string body, string? signature)
{
    var secretKey = config["Paystack:SecretKey"];
    if (string.IsNullOrEmpty(secretKey) || string.IsNullOrEmpty(signature)) return false;

    using var hmac = new HMACSHA512(Encoding.UTF8.GetBytes(secretKey));
    var expected = hmac.ComputeHash(Encoding.UTF8.GetBytes(body));

    byte[] received;
    try { received = Convert.FromHexString(signature); }
    catch (FormatException) { return false; }

    // Takes the same time however many bytes match, so it leaks nothing.
    return CryptographicOperations.FixedTimeEquals(expected, received);
}

Two smaller changes would follow. Salary transfers are matched to the ledger with Contains on a description, where an exact reference column would be safer. And the success event is published after the database save in a separate step, which can lose the event if the process stops in between; a transactional outbox, the pattern I use in the ticketing service, closes that gap.
